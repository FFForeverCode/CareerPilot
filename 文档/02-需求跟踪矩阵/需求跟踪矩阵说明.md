## 2. 工作表和模版的对应关系

模版有三类正文和若干图页。本矩阵保持同样的表名、列、批注、状态下拉和填写口径。

| 工作表 | 作用 |
| --- | --- |
| 需求跟踪矩阵封面 | 项目名称、版次、编制、审批、生效日期 |
| 变更履历 | 每次需求变更记一行，并统计初始、新增、删除、修改和变更比 |
| 设计用RTM | 按界面拆到功能点。一行一个可检查的界面行为 |
| 图1～图14 | 和「详细说明」里的「参照图、图标」对应 |

设计用 RTM 的列和模版一致：

| 列 | 模版含义 | 本矩阵怎么填 |
| --- | --- | --- |
| No. | 功能点序号 | 1～111。变更履历里的 RTM No. 指这一列 |
| 大分類（模块） | 界面 | 同一界面只在第一行写名称，下面留空 |
| 中分類（子模块） | 界面上的一块 | 沿用模版的 header、form、actions、hint、list、result 等。同一块只在第一行写 |
| 小分類（功能点） | 一个控件或一条可见规则 | 与对应图上的图标名称一致 |
| 详细说明 | 显示什么、用户做什么、约束是什么 | 以「参照图n，图标m」开头，末尾写需求编号 |
| PD | 点表头时提示「概要设计」 | 下拉：○、△、×、N/A |
| COD | 点表头时提示「编码」 | 同上 |
| UT | 点表头时提示「单体测试」，即单元测试 | 同上 |
| 担当者 | 做这一条的人 | 按需求定义书第 6 章的模块负责人 |
| 责任者 | 模版里固定为组长 | 全部为陈晓飞 |

表尾图例与模版相同：

- ○：完成（通过评审或测试）
- △：进行中
- ×：未着手
- N/A：不适用（没有此项活动）

2026-11-10 处于第 2 周，基线还未冻结，概要设计、编码和测试都还没开始，所以 111 行的 PD、COD、UT 都填 ×。某一列真正开始后，把该格改成 △；评审或测试通过后改成 ○。纯文档、没有设计或编码活动的行才能用 N/A。当前没有这种行。

## 8. 不进入本矩阵的事项

需求定义书第 2.2 节已经排除、变更履历第 1 行也写明不纳入的事项：

- 简历生成和修改，模拟面试打分
- 招聘网站爬虫、薪资和网申
- 多个智能体互相调用，向量库和文档检索
- Android、iOS、小程序
- 学校统一身份认证，短信或邮箱找回密码
- 心理诊断，以及考研、考公能否录取的预测
- 上传附件、语音、图片
- 学习任务、学习进度、技能差距清单

这些内容不分配 No.。以后若要加回来，先升需求定义书版本，再在变更履历里记新增条数和 RTM No.。No.49 只规定助手拒绝代写简历并打分，不表示本期要做简历功能。

## 10. 变更履历怎么填

第 1 行是 2026-11-10 建立基线，不是一次功能变更。

| 列 | 第 1 行 |
| --- | --- |
| 变更内容 | 按需求定义书 V1.1 建立矩阵；范围外事项不纳入 |
| RTM No. | 1-111 |
| 需求版本 | V1.1 |
| 变更人 | 陈晓飞 |
| 初始需求个数 | 111 |
| 新增、删除、修改 | 都是 0 |
| 总需求个数 | 111 |
| 需求变更比 | (新增 + 删除 + 修改) / 初始需求个数 = 0% |
| 对规模的影响 | 0 KLOC |
| 对工作量的影响 | 0 人日 |
| 对进度的影响 | 无影响，仍按 2026-11-03 至 2026-12-28 |

黄色格子是以后要填的。序号 2～20 已经留好。合计行对初始、新增、删除、修改、总需求五列做求和。变更比不要把各次比率再加总。

需求定义书附录里的 V0.1 到 V1.0 发生在本矩阵建立之前：V0.1 范围过大，V0.9 去掉简历、面试和爬虫，V1.0 形成功能基线，V1.1 把技术栈定为 Vue 3、Spring Boot、SQLite 和 Langchain4j。那些版本没有对应的 RTM No.，所以不拆进变更履历的删除个数。从下一次改需求开始，每一条都要能指到本表的 No.。

以后发生变更时，一行写清四件事：改了什么、对应哪些 No.、个数怎么变、对规模（KLOC）、工作量和进度有什么影响。只改状态列的 ○△×，不算需求变更，不用加履历。
